# 开发工作流

## 任务与分支

开始前核实仓库及远端、目标基线、当前分支与 HEAD、跟踪关系、工作区和暂存区。明确目标、授权及验收条件。保留已有改动，发现重叠时暂停相关写入并报告。

| 层级 | 职责 |
| --- | --- |
| 阶段 | 定义成果、验收与退出条件，可包含多个集成单元 |
| 集成单元 | 一个可独立审核、交付和回滚的目标，可包含多个实施任务及提交 |
| 实施任务 | 在确定范围内完成变更、验证和审核交接 |
| 提交 | 记录一组聚焦且已审核的变更 |

以 `main` 为长期分支。新集成单元从核实后的基线建立短期分支。同一集成单元的补充、修复和复验沿用原分支及已有 PR。目标、风险、审核或回滚边界实质变化时再评估拆分。

## 授权与停止条件

- 实施者默认在授权范围内修改和验证，保留未暂存、未提交的完整差异，交由独立审核者按原验收条件复审。审核要求修改时，在原分支复验并交接最新差异。
- Git 写操作及 GitHub 写操作须经明确授权，载明动作和对象。“完成任务”不构成写操作授权。合并和不合并关闭 PR 均须另行授权。避免直接向 `main` 提交或推送。禁止未经授权强推、改写历史或破坏性清理。
- 独立审核通过后，授权方可以一次性授权暂存、Commit、非强制 Push 及适用的 PR 操作。实施者只暂存经审核的任务文件，核对提交与已审核差异一致，推送专题分支后核对本地与远端 SHA。
- 正式部署、Pages、DNS、仓库权限和分支保护变更须独立授权。部署、域名、安全权限及依赖大版本变更先审核方案与回滚路径。PR CI 验证静态站点。
- 发生权限或工具不可用、远端 SHA 不符、范围漂移、必要检查缺失或失败、审核阻塞时，暂停受影响的操作，报告现状与原因。需要替代写入方式或扩大范围时取得明确授权。

只读审计以核实事实和检查证据为目标。限定在审计范围内读取资料并执行只读检查，保持工作区、Git 和外部记录原状。报告区分已确认事实、基于证据的分析判断和仍待核实的未知项。发现问题时记录依据与影响，实施修复另按授权进行。

## 验证与交付

按实际变化累计适用的验证。使用仓库声明的 Node.js 和 npm 版本。

| 变更 | 最低适用验证 |
| --- | --- |
| Markdown、文本规则 | 按[代码与工程文档规范](CODE_STYLE.md#markdown-审校)审校，核对 Git 差异及新增文件。格式规则另查 Git 属性、编码和行尾是否影响既有文件 |
| Astro、TypeScript、CSS、内容、依赖或构建配置 | `npm ci` 安装锁定依赖，运行 `npm run check`、`npm run build`，确认 `dist/index.html` 及受影响路由产物。补充与风险对应的回归检查 |
| 页面结构、布局、交互或可访问性 | 预览静态产物，按[官网 V1 规格](SITE_SPEC.md#v1-验收)记录适用的桌面、移动、导航和键盘检查 |
| 元数据、路由或发布 | 检查产物中的元数据、链接、路由、Sitemap 或 404。实际发布另按站点规格验证目标环境和回滚 |

- **任务门禁**。按任务目标验证，审查全部实际差异，记录环境、版本、命令、结果和未执行项。核对文件范围、空白、凭据、机器路径、日志及生成产物。未提交验证标明基线 HEAD 和实际差异。
- **集成检查点**。多个任务共同改变路由、公共布局、构建或发布行为时，在依赖任务继续前验证受影响的组合行为。已有证据足以覆盖当前组合时直接引用。
- **PR 最终门禁**。以实际最终 HEAD 验证原验收范围并核对必要 CI，记录 SHA、环境、执行时间、范围、结果和证据。HEAD 变化后重新核对差异并对当前 HEAD 取得适用证据。同一 HEAD、环境与验收范围下，创建 PR 和最终复审可复用同轮证据。

结束时至少核对 `git status --short`、`git diff --stat`、`git diff --check` 和暂存状态。交接说明实际范围、证据、未执行项、风险、遗留与下一步。构建结果与浏览器结果分别记录。

## 审核深度与风险

L1/L2/L3 决定审核覆盖面，可在发现新风险时提高深度。P0/P1/P2/P3 描述已发现问题的严重度，两者独立。

| 深度 | 适用情况与检查 |
| --- | --- |
| L1 | 低风险文档或局部调整，检查范围、事实、差异和适用证据 |
| L2 | 页面、公共组件、路由或构建行为变化，检查受影响调用方、关键路径及回归证据 |
| L3 | 发布、域名、安全权限或重大依赖变更，深入核对影响、验证环境和回滚路径 |

| 严重度 | 影响与处理 |
| --- | --- |
| P0 | 严重安全或隐私问题、站点整体不可用等。立即阻塞相关交付与阶段退出 |
| P1 | 核心目标无法达成或关键路径严重回归。修复并复验后再交付 |
| P2 | 影响有限且有可接受的规避方式。记录影响、延期理由与追踪方式 |
| P3 | 轻微体验、表述或维护问题。按需记录后续改进 |

实施任务完成以任务门禁及可审核交接为准。PR 合并另需最终门禁、独立复审和单独授权。阶段退出还需核实阶段范围已交付、全部验收和退出条件满足、相关集成单元审核通过、适用交付状态已核实，且没有未解决的 P0/P1。必需验证或验收缺口始终阻塞对应交付。已有证据满足退出条件时结束阶段，出现新回归、验收缺口或获准调整范围时再开启相关检查。

## Issue

需要跨 PR 跟踪的目标、独立缺陷、明确的技术债或研究事项可创建 Issue，写明目标、范围和完成条件。阶段级 Issue 可按交付项列清单。一个小 PR 可闭环的事项可直接在 PR 记录。

部分完成时使用链接或非关闭引用。全部关闭条件满足时才使用 `Closes #<issue>` 等关闭关键字或经授权关闭 Issue。决定取消时记录理由及适用状态。

## Pull Request

首次创建 PR 前，核实目标分支、远端来源分支与 SHA、完整差异、文件范围和最终验证证据。同一来源分支经授权 Push 后会更新已有 PR。目标、范围、证据或风险有变化时，经授权同步正文。提交和 PR 标题采用简化 Conventional Commits，例如 `chore: 初始化 Astro 官网工程`。

独立审核者默认在授权范围内创建、更新和跟踪 PR。按[模板](../.github/PULL_REQUEST_TEMPLATE.md)填写目标与完成条件、主要变更、实际验证及未执行项、风险与未完成项，以及适用的 Issue、依赖 PR 或正式证据链接。长期写作与证据引用遵循[代码与工程文档规范](CODE_STYLE.md#事实来源与长期记录)。

合并前，独立审核者核对实际 Base/Head、最终 HEAD、完整差异、原验收条件、最终门禁证据及阻塞项。取得适用授权后，独立审核者将最终复审结论作为 GitHub PR Conversation 评论发布，记录审核对象、通过或阻塞的结论、变更边界、关键变更、验证证据和风险遗留。最终 HEAD 变化后重新复审。可合并的审核结论是申请合并授权的依据。

## 文档同步

变更改变已描述的产品范围、行为、配置或工程约束时，同步直接受影响的权威文档。出现疑似漂移时先局部复核。核心事实明显失真、多份规范互相冲突、产品或技术边界重大变化，或准备首次正式发布时，按独立目标进行低频只读审计，再处理确认的问题。需要长期依赖的技术实验在对应正式文档记录环境、观察结果和适用边界。

## 状态恢复

以正式文档恢复长期决策和范围，以 Git、源码、配置与可复核验证恢复版本和实现，以适用 Issue 恢复持续目标与关闭条件，以 PR 恢复集成差异、审核、CI 和交付状态。重做任务开始检查，核对本地暂存、未暂存与未跟踪变化，识别既有证据所对应的版本。对照实际状态确认已完成、待验证、阻塞事项和下一步。

临时交接仅补充正式来源无法恢复的意图、待同步事项和操作线索，注明适用版本。无法访问或相互冲突的事实记为未知，暂停依赖该事实的写入或交付。

## 仓库外审核产物

优先使用 ChatGPT 能直接、完整取得的 GitHub 差异。若 GitHub 无法覆盖本次完整差异，且 ChatGPT 无法直接读取工作区，Codex 在本次任务结束前生成完整审核产物。GitHub 已完整覆盖的基线差异可直接引用。

- 优先提供一份完整补丁，标明比较基线，覆盖本任务全部新增、修改、删除及适用的暂存与未跟踪内容。必要时补充最小清单或等价文件。核对文件集合与实际差异一致，并验证产物能还原变更。
- 审核包根目录固定为 Git 仓库根目录的同级目录，从仓库根目录相对引用为 `../ezhub_review_artifacts/`。每个集成单元使用独立子目录。主补丁从 `r001.patch` 起，按最大已用编号递增为 `r002.patch` 等，同轮补充材料使用相同前缀。审核包不得默认存入 Git 仓库内部。固定目录不可访问或无法安全写入时，报告阻断原因，不自行改用其他目录。产物不得进入 Git 或包含凭据及无关内容。
- 最终报告指明当前审核版本，并提供每份审核包可直接复制的绝对路径、文件大小、SHA-256 和实际覆盖范围。
- 审核与交付期间保留各轮产物。最终审核、合并及本地收尾完成后，按明确授权清理对应集成单元的产物。写入或清理前核对规范化绝对路径，检查目标、父路径与相关目录内的符号链接、Junction 和其他重解析点。仅操作仓库外专用目录内已核实的集成单元子目录。待审核材料或尚未归档的独有证据继续保留。
