# 开发工作流

## 开始任务

核实远端基线、当前分支、HEAD、工作区和暂存区，明确授权范围与验收条件。以 `main` 为长期分支，从核实后的基线建立短期分支。已有改动与任务重叠时暂停相关写入并报告。每个变更聚焦一个可独立审核和回滚的目标，按当前需求控制工程复杂度。

## 验证与交付

- 用 `npm ci` 安装锁定依赖，运行 `npm run check` 和 `npm run build`，确认 `dist/index.html` 存在。布局、交互和响应式变更记录适用的桌面与移动浏览器验证。文档变更复核事实与链接。
- 提交前核对文件边界、空白问题和敏感信息。保护用户已有修改，排除凭据、机器路径、日志和生成产物。
- 区分已执行结果与未执行项，记录适用命令、环境和验证对象。未提交验证注明基线与实际差异。审核与证据对应最终 HEAD，HEAD 变化后复核受影响的证据。必需验证失败或缺失时暂停交付并报告。
- 按授权分别执行分支创建、暂存与提交、非强制 Push、PR 操作和合并。提交主题使用简化的 Conventional Commits，例如 `chore: 初始化 Astro 官网工程`。避免直接向 `main` 提交或推送、改写历史及破坏性清理。

## PR 与审核

Codex 提供变更和验证证据。ChatGPT 默认在授权范围内创建、更新和跟踪 PR，并负责需要的独立审核。用户决定合并与发布授权。PR 按[模板](../.github/PULL_REQUEST_TEMPLATE.md)记录目标、变更、验证和遗留事项。

普通文案由用户核对内容。布局、交互和响应式变更结合浏览器证据独立审核。部署、域名、安全权限和依赖大版本变更在实施前审核方案与回滚路径，实施后审核最终差异及验证证据。

PR CI 仅验证静态站点。正式部署及 Pages、DNS、分支保护和组织权限变更需要独立授权。
