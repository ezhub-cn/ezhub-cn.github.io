# 开发工作流

## 开始任务

核实远端基线、当前分支、HEAD、工作区和暂存区，明确授权范围与验收条件。保护已有改动，发现与任务重叠时暂停相关写入并报告。

以 `main` 为长期分支。一个可独立审核和回滚的目标构成一个集成单元，新集成单元从核实后的基线建立短期分支。同一集成单元的修复、补充与复验继续使用原分支及已有 PR。目标、风险或回滚边界实质变化时再评估是否拆分。

## Git 授权与独立审核

1. 实施任务默认只包含授权范围内的文件修改与验证。暂存、提交、Push 与 PR 创建的授权在独立审核通过后取得。任务提示词如涉及 Git 写操作，须载明用户明确授权的动作和对象。“完成任务”不构成任何 Git 写操作的授权。避免直接向 `main` 提交或推送、改写历史及破坏性清理。
2. Codex 完成实施和验证后，默认保留未暂存、未提交的改动，交给 ChatGPT 按完整差异与原验收标准独立审核。审核要求修改时，在同一分支复验并交接更新后的差异。
3. 独立审核通过后，用户可一次性明确授权暂存与 Commit、非强制 Push 和创建 PR。Codex 仅暂存已审核的任务文件，核对提交与已审核差异一致，推送专题分支并核对本地与远端 SHA。ChatGPT 默认负责在授权范围内创建、更新和跟踪 PR。已有 PR 随同一分支推送更新。提交主题使用简化的 Conventional Commits，例如 `chore: 初始化 Astro 官网工程`。
4. 合并前，ChatGPT 核对 PR 的实际最终 HEAD、完整差异、原验收要求及对应证据，并记录独立审核结论。HEAD 变化后重新核对差异与适用验证。必需检查缺失、失败或存在阻塞问题时，暂停交付。Merge 始终需要用户另行明确授权。

## 验证与交付

- 工程变更用 `npm ci` 安装锁定依赖，运行 `npm run check` 和 `npm run build`，确认 `dist/index.html` 存在。布局、交互和响应式变更记录适用的桌面与移动浏览器验证。纯文档变更审校事实、语言与内部链接，并检查 Git 差异。
- 交接前核对文件边界、空白问题和敏感信息，排除凭据、机器路径、日志和生成产物。报告实际命令、环境、结果、未执行项及原因。未提交验证注明基线 HEAD 与实际差异，PR 验收记录实际最终 HEAD。
- PR 按[模板](../.github/PULL_REQUEST_TEMPLATE.md)记录目标、变更、验证和遗留事项。普通文案由用户核对内容。部署、域名、安全权限和依赖大版本变更在实施前审核方案与回滚路径。

## 仓库外审核产物

优先使用 ChatGPT 能直接、完整取得的 GitHub 差异。若 GitHub 无法覆盖本次完整差异，且 ChatGPT 无法直接读取工作区，Codex 在本次任务结束前生成完整审核产物。GitHub 已完整覆盖的基线差异可直接引用。

- 优先提供一份完整补丁，标明比较基线，覆盖本任务全部新增、修改、删除及适用的暂存与未跟踪内容。必要时补充最小清单或等价文件。核对文件集合与实际差异一致，并验证产物能还原变更。
- 审核包根目录固定为 Git 仓库根目录的同级目录，从仓库根目录相对引用为 `../ezhub_review_artifacts/`。每个集成单元使用独立子目录。主补丁从 `r001.patch` 起，按最大已用编号递增为 `r002.patch` 等，同轮补充材料使用相同前缀。审核包不得默认存入 Git 仓库内部。固定目录不可访问或无法安全写入时，报告阻断原因，不自行改用其他目录。产物不得进入 Git 或包含凭据及无关内容。
- 最终报告指明当前审核版本，并提供每份审核包可直接复制的绝对路径、文件大小、SHA-256 和实际覆盖范围。
- 审核与交付期间保留各轮产物。最终审核、合并及本地收尾完成后，按明确授权清理对应集成单元的产物。写入或清理前核对规范化绝对路径，检查目标、父路径与相关目录内的符号链接、Junction 和其他重解析点。仅操作仓库外专用目录内已核实的集成单元子目录。待审核材料或尚未归档的独有证据继续保留。

## 部署与仓库设置

PR CI 仅验证静态站点。正式部署及 Pages、DNS、分支保护和组织权限变更需要独立授权。
